01 / The idea

Learn from the cases that make ReID fail.

Abstract

Clothes-changing person re-identification must match people across cameras despite drastic outfit changes. MINER focuses training on visually similar different people and visually dissimilar outfits of the same person.

It samples these hard cases stochastically at the centroid level, then applies a symmetric multi-positive contrastive loss. The main novelty is an online Variance Controller that adapts the number of identities and examples per identity from the estimated balance between discrimination and invariance errors.

Hard example miningEffective image batch selection for identity representation

MINER deliberately fills each batch with two complementary signals: hard positives (same person, different outfits) to improve invariance, and hard negatives (different people, similar appearance) to improve discrimination.

Hard positivesame identity · different clothes
↔ same person

These cross-outfit matches are intentionally visually far apart, so the encoder learns to keep identity stable across clothing changes.

Hard negativedifferent identities · similar appearance
≈ look-alike

These identities are intentionally visually close, so the encoder learns to separate people even when clothing and overall appearance are misleading.

In one sentence: hard positives reduce invariance error, hard negatives reduce discrimination error, and MINER learns from both at once.
Multi-positive contrastive lossall valid same-identity query–gallery matches contribute
Why it matters: instead of pulling each query toward only one selected positive, MINER treats all valid same-identity gallery images as positives, producing the block-diagonal supervision pattern shown above.
ASSUMING FIXED GPU MEMORY BUDGETNo matter what's your training budget, the GPU memory remains constant throughout the finetune in most cases. How to leverage it effectively is the challenge we address now.
Main novelty · the Variance Controlleranalytic online update

Instead of fixing one batch composition for every dataset, MINER estimates two error sources online and allocates the same batch budget to where it matters most.

Invariance errorToo few cross-outfit examples per identity means the model under-learns outfit invariance.within-person term ∝ tr Σ_W / (2n)
↔
Discrimination errorToo few identities per batch means the model sees too few look-alike negatives.between-person term ∝ tr Σ_B / m

Estimate

Compute online traces for the within-person and between-person gradient variance terms from the mined batch.

risk(m,n) = tr Σ_B / m + tr Σ_W / (2n) subject to 2mn = B_max

Infer the prior

The ratio between the two estimators reveals whether the current dataset prefers more identities or more examples per identity.

ρ = 2 tr Σ_B / tr Σ_W ρ small → favor n ρ large → favor m

Update analytically

The controller solves for the new allocation in closed form under the fixed memory budget.

m* = √(B_max · tr Σ_B / tr Σ_W) n* = √(B_max · tr Σ_W / 4 tr Σ_B)
No Grid-SearchNo RLNo multi-armed banditNo extra learner
Why this matters: MINER does not balance these tradeoffs with an additional learning policy. It estimates the two variance terms online and updates the allocation directly, which keeps the controller lightweight, interpretable, and easy to reproduce.
02 / The variance controller

Each dataset has its own optimal intra- vs. inter-person prior.

Different datasets induce different balances between invariance and discrimination errors. The controller uses the estimated ratio between them to move toward a dataset-specific allocation instead of reusing a universal m:n split.

Read the plots: each point is a measured mAP result from the paper's fixed-allocation sweep. The highlighted point is the best measured allocation for that dataset.

Invariance-driven regime

When the within-person term dominates, the model benefits from more samples per identity to better connect outfit changes.

smaller ρ → larger n
Discrimination-driven regime

When the between-person term dominates, the model benefits from more identities per batch to sharpen separation.

larger ρ → larger m
Controller takeaway

The controller is analytic: estimate the two variance terms, compute ρ, and update m:n under the batch budget.

No Grid-Search · No RL · No bandit policy · No extra optimization loop
